# 컴퓨팅 & 스케일링

## EC2 인스턴스 패밀리

| 패밀리 | 특징 | 용도 |
|--------|------|------|
| C (Compute) | 고성능 CPU | 과학 계산, 게임 서버 |
| M (General) | 균형 CPU/메모리 | 웹 서버, 소형 DB |
| R (Memory) | 고메모리 | 인메모리 DB, 빅데이터 |
| I (Storage) | NVMe 고속 스토리지 | NoSQL DB, 데이터 웨어하우스 |
| G/P (GPU) | GPU | ML 학습, 그래픽 렌더링 |
| T (Burstable) | 기준 성능 + 버스트 | 개발, 소규모 앱 |

> [!tip] 메모리 최적화 선택
> "대용량 인메모리 처리" → R 패밀리
> "캐시, SAP HANA" → R 또는 X 패밀리

## EC2 배치 그룹 (Placement Group)

| 유형 | 배치 전략 | 용도 |
|------|-----------|------|
| Cluster | 동일 AZ, 같은 랙 | 초저지연 HPC (단, 랙 장애 시 모두 영향) |
| Spread | 각 인스턴스 다른 랙 | 중요한 소수 인스턴스 격리 (최대 7/AZ) |
| Partition | 파티션별 랙 격리 | 대규모 분산 시스템 (Kafka, Hadoop) |

> [!important] Cluster vs Spread
> Cluster: 성능 최우선, HA 낮음
> Spread: HA 최우선, 소수 인스턴스

## Lambda 고성능

### Lambda 동시성
```
기본 동시성: 계정당 1,000 (리전별)
예약된 동시성: 특정 함수 상한 보장
프로비저닝된 동시성: 콜드 스타트 제거 (미리 초기화)
```

> [!tip] 콜드 스타트 해결책
> 프로비저닝된 동시성: 추가 비용이지만 콜드 스타트 없음

### Lambda 한계
| 항목 | 한도 |
|------|------|
| 최대 실행 시간 | 15분 |
| 메모리 | 128MB ~ 10GB |
| 임시 스토리지 (/tmp) | 최대 10GB |
| 배포 패키지 | 50MB (zip), 250MB (unzipped) |

> [!warning] Lambda 부적합 사례
> - 15분 초과 작업 → EC2, ECS, Step Functions
> - 상태 유지 필요 → ECS/EC2 (Lambda는 무상태)

## ECS vs EKS vs Fargate

| 항목 | ECS | EKS | Fargate |
|------|-----|-----|---------|
| 관리 | AWS 독자 | Kubernetes | 서버리스 (인프라 없음) |
| 학습 곡선 | 낮음 | 높음 (K8s) | 매우 낮음 |
| EC2 사용 | ✅ | ✅ | ❌ (서버리스) |
| 서버리스 | ECS+Fargate | EKS+Fargate | ✅ |

> [!tip] 선택 기준
> "관리 오버헤드 최소화, 컨테이너" → ECS + Fargate
> "기존 Kubernetes 사용" → EKS
> "서버 관리 없이 컨테이너" → Fargate
