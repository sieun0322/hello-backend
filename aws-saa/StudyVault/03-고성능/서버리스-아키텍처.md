# 서버리스 아키텍처

## 서버리스 서비스 전체 맵

```
API 계층:    API Gateway
컴퓨팅:      Lambda, Fargate
스토리지:    S3, DynamoDB
메시징:      SQS, SNS, EventBridge
오케스트레이션: Step Functions
인증:        Cognito
```

## API Gateway

### 엔드포인트 유형
| 유형 | 특징 | 용도 |
|------|------|------|
| 엣지 최적화 | CloudFront 자동 연동 | 글로벌 클라이언트 |
| 리전 | 리전 내 최적화 | 동일 리전 클라이언트 |
| 프라이빗 | VPC 내부 전용 | 내부 API |

### 주요 기능
- **스테이지**: dev/staging/prod 환경 분리
- **사용 계획 + API 키**: 쿼터/스로틀링 제어
- **캐싱**: 응답 캐시 (TTL 설정)
- **통합 유형**: Lambda, HTTP, AWS 서비스, Mock

> [!tip] API Gateway + Lambda = 표준 서버리스 패턴
> REST API 또는 HTTP API (더 저렴, 기능 제한)

## Step Functions

```
상태 머신 (State Machine)
├── Task 상태: Lambda, ECS, SNS 등 호출
├── Choice 상태: 조건 분기
├── Wait 상태: 대기
├── Parallel 상태: 병렬 실행
└── Map 상태: 배열 반복 처리
```

> [!important] Step Functions vs SQS
> Step Functions: 복잡한 워크플로우, 상태 추적, 오류 처리
> SQS: 단순 메시지 큐, 순서 없는 작업

### Express vs Standard Workflows
| 항목 | Standard | Express |
|------|----------|---------|
| 실행 시간 | 최대 1년 | 최대 5분 |
| 실행 보장 | 정확히 한 번 | 최소 한 번 |
| 과금 | 상태 전환당 | 실행 수/시간 |
| 용도 | 장기 워크플로우 | 고빈도 단기 |

## EventBridge (CloudWatch Events 후속)

```
이벤트 소스 (S3, EC2, 커스텀)
    ↓
EventBridge 버스
    ↓
규칙 (필터링)
    ↓
대상 (Lambda, SQS, SNS, Step Functions, ECS...)
```

> [!tip] EventBridge vs SNS
> EventBridge: 이벤트 기반, 풍부한 필터링, 여러 대상
> SNS: 단순 Pub/Sub, 팬아웃

## 서버리스 아키텍처 패턴

### 표준 CRUD API
```
클라이언트 → API Gateway → Lambda → DynamoDB
```

### 비동기 처리
```
클라이언트 → API Gateway → Lambda → SQS → Lambda (처리)
```

### 이벤트 기반
```
S3 업로드 → EventBridge → Lambda (썸네일 생성)
                        → Lambda (메타데이터 추출)
                        → SQS (알림 큐)
```

## 시험 함정

> [!warning]- 서버리스 함정
> - **Lambda 15분 제한**: 장기 작업은 ECS/Step Functions
> - **API Gateway 타임아웃**: 29초 (Lambda와 다름)
> - **Step Functions 비용**: Standard는 상태 전환당 과금 → 고빈도엔 Express
> - **EventBridge vs CloudWatch Events**: 같은 서비스, EventBridge가 새 이름
