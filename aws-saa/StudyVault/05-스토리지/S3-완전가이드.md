# S3 완전 가이드

## S3 기본

### 버킷 & 객체
- 버킷: 글로벌 고유 이름, 리전에 위치
- 객체 최대 크기: **5TB**
- 단일 PUT: 최대 **5GB** → 초과 시 **멀티파트 업로드** 필수
- 멀티파트 권장: **100MB** 이상

### 버전 관리 (Versioning)
- 동일 키 객체의 모든 버전 보관
- 삭제 시: 삭제 마커 추가 (실제 삭제 아님)
- 영구 삭제: 특정 버전 ID 지정 삭제
- MFA Delete: 버전 삭제에 MFA 필요 (추가 보호)

## 보안

### 버킷 정책 vs ACL vs 액세스 포인트
| 방식 | 적용 레벨 | 사용 시나리오 |
|------|-----------|---------------|
| 버킷 정책 | 버킷 전체 | 교차 계정 접근, IP 제한 |
| ACL | 객체 수준 | 레거시 (권장 안 함) |
| S3 액세스 포인트 | VPC/계정별 | 데이터 레이크 다중 팀 접근 |

> [!important] 퍼블릭 액세스 차단 설정
> 계정/버킷 레벨에서 퍼블릭 액세스 차단 → 버킷 정책도 public 불가

### Pre-signed URL
```
생성: SDK/CLI로 임시 서명된 URL 생성 (기본 1시간)
활용: 비공개 객체 임시 공유
```

### S3 Object Lock
- **WORM (Write Once Read Many)**: 덮어쓰기/삭제 방지
- Compliance 모드: 루트도 삭제 불가 (규정 준수)
- Governance 모드: 특정 권한으로 삭제 가능

## 성능 최적화

### S3 Transfer Acceleration
```
클라이언트 → CloudFront 엣지 → S3 버킷 (빠른 내부 네트워크)
```
- 글로벌 → 단일 버킷 빠른 업로드
- 추가 비용 발생

### 멀티파트 업로드
```
큰 파일 → 파트 분할 → 병렬 업로드 → 완료 후 병합
```
- 재시도 효율적 (실패한 파트만 재전송)

### S3 요청 성능
- 접두사(prefix) 별로 초당 3,500 PUT/5,500 GET 지원
- 접두사 다양화로 성능 향상 (날짜/해시 기반)

## 이벤트 알림

```
S3 이벤트 (PUT/DELETE 등)
    ↓
SNS / SQS / Lambda / EventBridge
```

> [!tip] EventBridge vs 직접 알림
> EventBridge: 더 많은 대상, 필터링, 여러 대상 동시 전송

## 정적 웹사이트 호스팅

```
S3 정적 웹사이트
    ↓ (선택)
CloudFront + HTTPS
    ↓
Route 53 (커스텀 도메인)
```

> [!important] HTTPS 필요 시
> S3 단독 → HTTP만 지원
> CloudFront + ACM → HTTPS 지원

## 데이터 처리

### S3 Select
- SQL로 객체 내 **일부 데이터만** 검색
- 전체 객체 다운로드 없이 필요한 데이터만 (비용/성능 절감)

## 시험 함정

> [!warning]- S3 함정 모음
> - **버킷 이름**: 전역 고유 (리전과 무관)
> - **CRR/SRR**: 버전 관리 필수, 기존 객체 미복제 (신규만)
> - **Glacier 즉시 검색**: Glacier Instant Retrieval 사용 (Flexible은 분~시간)
> - **멀티파트**: 완료 호출 안 하면 불완전 파트 과금 → Lifecycle로 자동 삭제
> - **퍼블릭 버킷 정책**: 퍼블릭 액세스 차단 설정이 버킷 정책보다 우선
