# 데이터 이전 서비스

## AWS DataSync

- **온프레미스 ↔ AWS 파일 데이터 전송** (NFS, SMB)
- 자동: 압축, 암호화, 검증
- 대역폭 제어 가능 (업무 시간 외 전송)
- 대상: S3, EFS, FSx
- 예약 전송 지원 (주기적 동기화)

> [!tip] DataSync vs Storage Gateway
> DataSync: 일회성/주기적 **데이터 이전**
> Storage Gateway: 지속적 **하이브리드 스토리지** 통합

## AWS Snow Family

| 서비스 | 용량 | 연산 | 용도 |
|--------|------|------|------|
| Snowcone | 8 TB (HDD) / 14 TB (SSD) | 엣지 컴퓨팅 | 소규모, 오지 환경 |
| Snowball Edge Storage | 80 TB | 스토리지 최적화 | 대용량 데이터 이전 |
| Snowball Edge Compute | 40 TB | 컴퓨팅 최적화 | 엣지 ML/전처리 |
| Snowmobile | 100 PB | - | 데이터센터 이전 |

> [!important] Snowball vs DataSync 선택
> 인터넷 속도 < 대역폭 필요 → **Snowball** (물리 디바이스)
> 온라인 전송 가능 → **DataSync**
> 일반 기준: 전송 시간 > 1주일이면 Snowball 고려

## AWS Storage Gateway

### 유형별 비교

| 유형 | 프로토콜 | 사용 사례 |
|------|----------|-----------|
| S3 File Gateway | NFS/SMB | 온프레미스 → S3 (파일로 접근) |
| FSx File Gateway | SMB | 온프레미스 → FSx for Windows (로컬 캐시) |
| Volume Gateway (Cached) | iSCSI | S3 기반 볼륨, 자주 쓰는 데이터 로컬 캐시 |
| Volume Gateway (Stored) | iSCSI | 로컬 저장 + 비동기 S3 백업 |
| Tape Gateway | iSCSI (VTL) | 기존 테이프 백업 → S3/Glacier |

> [!tip] 시험 패턴
> "온프레미스 백업을 AWS로" → Tape Gateway (기존 백업 소프트웨어 유지)
> "온프레미스에서 S3를 파일 서버처럼" → S3 File Gateway
> "DR: 온프레미스 볼륨 S3 백업" → Volume Gateway Stored

## AWS Transfer Family

- SFTP, FTPS, FTP로 **S3 또는 EFS** 접근
- 기존 FTP 클라이언트 코드 변경 없이 AWS 스토리지 연결

## 마이그레이션 서비스

| 서비스 | 대상 | 특징 |
|--------|------|------|
| AWS DMS | 데이터베이스 | 이기종 DB 마이그레이션, 지속적 복제 |
| AWS MGN (Application Migration) | 서버 전체 | 리프트앤시프트, 서버 → EC2 |
| AWS Application Discovery | 온프레미스 인벤토리 | 마이그레이션 계획 수립 |
| AWS Migration Hub | 마이그레이션 추적 | 중앙 대시보드 |

> [!important] DMS 핵심
> - 동종 마이그레이션: MySQL → MySQL
> - 이기종 마이그레이션: Oracle → Aurora (+ Schema Conversion Tool)
> - 마이그레이션 중 소스 DB 계속 운영 가능

## 시험 함정

> [!warning]- 데이터 이전 함정
> - **DataSync 대역폭 제어**: 업무 시간 중 영향 최소화 가능
> - **Snowball**: 인터넷 전송 아님 → 물리 디바이스로 AWS로 배송
> - **Storage Gateway**: VM 또는 하드웨어 어플라이언스로 온프레미스 배포
> - **DMS**: 마이그레이션 중 소스 DB 계속 운영 가능 (최소 다운타임)
