# 스토리지 비용 최적화

## S3 스토리지 클래스 비교

| 클래스 | 가용성 | 최소 보관 | 검색 시간 | 용도 |
|--------|--------|-----------|-----------|------|
| Standard | 99.99% | 없음 | 즉시 | 자주 접근 |
| Standard-IA | 99.9% | 30일 | 즉시 | 가끔 접근, 빠른 검색 필요 |
| One Zone-IA | 99.5% | 30일 | 즉시 | 재생성 가능 데이터 |
| Intelligent-Tiering | 99.9% | 없음 | 즉시/분 | 접근 패턴 불예측 |
| Glacier Instant | 99.9% | 90일 | 즉시 | 아카이브, 즉시 검색 |
| Glacier Flexible | 99.99% | 90일 | 분~시간 | 아카이브, 검색 유연 |
| Glacier Deep Archive | 99.99% | 180일 | 12~48시간 | 장기 보관 (7~10년) |

> [!important] 핵심 포인트
> - **Intelligent-Tiering**: 접근 패턴이 **예측 불가**할 때 → 자동 계층 이동
> - **One Zone-IA**: 가용 영역 1개 → 가장 저렴, 재생성 가능 데이터만
> - **Glacier Deep Archive**: 가장 저렴, 12시간 검색 감수 가능 시

## S3 Lifecycle 정책

```
업로드 → Standard
  ↓ 30일
Standard-IA
  ↓ 90일
Glacier Flexible Retrieval
  ↓ 365일
삭제
```

> [!tip] Lifecycle 규칙 제한
> Standard → Standard-IA: 최소 **30일** 유지 후 이동 가능

## EBS 비용 최적화

| 볼륨 유형 | 용도 | 비용 |
|-----------|------|------|
| gp3 | 범용 SSD (gp2 대체) | gp2보다 20% 저렴 |
| gp2 | 범용 SSD (구버전) | gp3로 마이그레이션 권장 |
| io2 Block Express | 고성능 DB | 고가 |
| st1 | 처리량 최적화 HDD | 저렴 (순차 대용량) |
| sc1 | 콜드 HDD | 가장 저렴 (아카이브) |

> [!tip] gp2 → gp3 전환
> gp3: IOPS와 처리량을 **독립적으로** 설정 가능 (비용 절감)

## 데이터베이스 비용 최적화

| 전략 | 방법 |
|------|------|
| RDS | Reserved 인스턴스 (1년/3년) |
| Aurora | Serverless v2 (가변 워크로드) |
| DynamoDB | On-Demand (예측 불가) vs Provisioned + Auto Scaling |
| Redshift | Reserved 노드, 일시정지 기능 |

## 시험 함정

> [!warning]- 스토리지 비용 함정
> - **One Zone-IA**: AZ 장애 시 데이터 손실 → 재생성 가능 데이터만
> - **Glacier 최소 보관**: 90일 미만 삭제 시 잔여 기간 요금 부과
> - **Intelligent-Tiering**: 소형 객체(128KB 미만)엔 비효율 (모니터링 비용)
> - **EBS**: 인스턴스 종료 후에도 과금 → 스냅샷 후 삭제 고려
