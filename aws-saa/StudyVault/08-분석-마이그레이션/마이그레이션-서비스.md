# 마이그레이션 서비스

## 7R 마이그레이션 전략

| 전략 | 설명 | 예시 |
|------|------|------|
| Retire | 폐기 | 사용 안 하는 앱 종료 |
| Retain | 유지 | 규정상 온프레미스 유지 |
| Rehost | 리프트앤시프트 | EC2로 그대로 이전 (MGN) |
| Relocate | 플랫폼 이전 | VMware → VMware Cloud on AWS |
| Replatform | 리프트앤리셰이프 | DB → RDS (OS 관리 없앰) |
| Refactor/Re-architect | 재설계 | 모놀리스 → 마이크로서비스 |
| Repurchase | 재구매 | 자체 CRM → Salesforce SaaS |

## AWS DMS (Database Migration Service)

### 마이그레이션 유형
| 유형 | 소스 → 대상 | 도구 |
|------|-------------|------|
| 동종 | MySQL → RDS MySQL | DMS만 |
| 이기종 | Oracle → Aurora PostgreSQL | SCT + DMS |

### 연속 복제 (CDC)
```
소스 DB (운영 중) → DMS → 대상 DB (복제 중)
                     ↑
              Change Data Capture (CDC)
→ 마이그레이션 완료 후 전환 (최소 다운타임)
```

> [!important] SCT (Schema Conversion Tool)
> 이기종 마이그레이션 시 스키마/코드 자동 변환
> 변환 불가 항목 → 수동 처리 필요

## AWS MGN (Application Migration Service)

- 서버 전체를 **EC2로 리프트앤시프트**
- 에이전트 설치 → 지속적 복제 → 컷오버
- 최소 다운타임 마이그레이션
- AWS Server Migration Service (SMS) 후속

## AWS Application Discovery Service

- 온프레미스 서버 인벤토리 수집
- 에이전트리스 (VMware) 또는 에이전트 기반
- Migration Hub로 데이터 전송

## AWS Migration Hub

- 마이그레이션 진행상황 **중앙 추적**
- DMS, MGN, Discovery Service 통합 뷰

## 데이터 마이그레이션 의사결정 트리

```
온라인 전송 가능?
├── 예 → DataSync (파일), DMS (DB)
└── 아니오 (대용량 / 느린 네트워크)
         ↓
     Snow Family
     ├── < 10TB → Snowcone
     ├── < 80TB → Snowball Edge
     └── > 10PB → Snowmobile
```

## 마이그레이션 단계별 서비스

| 단계 | 서비스 |
|------|--------|
| 발견 | Application Discovery, Migration Evaluator |
| 계획 | Migration Hub, Migration Evaluator |
| 마이그레이션 | DMS, MGN, DataSync, Snowball |
| 최적화 | Trusted Advisor, Compute Optimizer |

## 시험 함정

> [!warning]- 마이그레이션 함정
> - **DMS vs DataSync**: DMS는 DB 마이그레이션, DataSync는 파일 마이그레이션
> - **MGN vs DMS**: MGN은 서버 전체, DMS는 DB만
> - **이기종 마이그레이션**: SCT 먼저 → DMS로 데이터 이전
> - **CDC**: 소스 DB를 운영하면서 마이그레이션 (다운타임 최소화)
