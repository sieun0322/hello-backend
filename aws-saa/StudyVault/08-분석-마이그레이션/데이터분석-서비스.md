# 데이터 분석 서비스

## 데이터 레이크 아키텍처

```
데이터 소스 (S3, RDS, DynamoDB...)
    ↓
AWS Glue (ETL, 카탈로그)
    ↓
S3 데이터 레이크
    ├── Athena (SQL 쿼리)
    ├── Redshift Spectrum (DW 쿼리)
    ├── EMR (빅데이터 처리)
    └── QuickSight (시각화)
```

## AWS Glue

### 핵심 컴포넌트
| 컴포넌트 | 역할 |
|----------|------|
| Glue Data Catalog | 메타데이터 저장소 (스키마 관리) |
| Glue ETL Jobs | Spark 기반 데이터 변환 |
| Glue Crawlers | 데이터 소스 자동 스캔 → 카탈로그 등록 |
| Glue Studio | 시각적 ETL 설계 도구 |

> [!tip] Glue Crawler 역할
> S3/RDS/DynamoDB 등 스캔 → 스키마 자동 감지 → Data Catalog 업데이트

### Glue DataBrew
- 코드 없이 데이터 정제/변환 (시각적 도구)
- 데이터 프로파일링 (품질 분석)

## Amazon Athena

- S3 데이터에 **서버리스 SQL 쿼리** (설치 불필요)
- 과금: **스캔된 데이터양** 기준 (쿼리당)
- 지원 형식: CSV, JSON, ORC, Parquet, Avro

### 비용 최적화
```
컬럼 형식 (Parquet, ORC) → 스캔 데이터 감소 → 비용 절감
파티셔닝 → 필요한 파티션만 스캔
압축 → 스캔 데이터 감소
```

> [!important] Athena vs Redshift
> Athena: 임시 쿼리, 서버리스, S3 직접
> Redshift: 반복 쿼리, 복잡한 JOIN, 사전 로드 필요

## Amazon EMR (Elastic MapReduce)

- 관리형 **Hadoop, Spark, HBase** 클러스터
- 대규모 데이터 처리 (ETL, ML, 로그 분석)

### 클러스터 구성
```
마스터 노드 (1개): 클러스터 관리, 리소스 할당
코어 노드: HDFS + 처리
태스크 노드: 처리만 (Spot 사용 가능)
```

> [!tip] EMR 비용 최적화
> 태스크 노드 → Spot 인스턴스 사용 (최대 90% 절감)

## AWS Lake Formation

- 데이터 레이크 **보안 및 거버넌스** 중앙화
- 세밀한 접근 제어: 열/행 수준 권한
- Glue Data Catalog 위에 구축

> [!tip] Lake Formation vs Glue
> Glue: ETL + 카탈로그 관리
> Lake Formation: 카탈로그 + **보안/거버넌스** 추가

## Amazon OpenSearch Service

- Elasticsearch 기반 검색/분석 엔진
- 로그 분석, 전체 텍스트 검색, 시각화 (Kibana/OpenSearch Dashboards)
- 실시간 분석에 적합

## Amazon QuickSight

- **서버리스 BI 도구** (비즈니스 인텔리전스)
- S3, Athena, RDS, Redshift 등 연결
- 대시보드, 차트, ML 인사이트 (이상 탐지)

## 시험 함정

> [!warning]- 분석 서비스 함정
> - **Athena 비용**: 스캔 데이터양 → Parquet/ORC + 파티셔닝으로 절감
> - **Glue vs DMS**: Glue는 ETL(데이터 변환), DMS는 DB 마이그레이션
> - **EMR vs Glue**: EMR은 더 많은 제어권, Glue는 서버리스 ETL
> - **OpenSearch**: RDS/DynamoDB 복제 → 검색 최적화 (풀텍스트 검색)
