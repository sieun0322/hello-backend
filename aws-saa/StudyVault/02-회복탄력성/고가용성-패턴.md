# 고가용성 패턴

## 핵심 원칙

> [!important] HA 3요소
> 1. **중복성**: 여러 AZ에 리소스 분산
> 2. **자동 복구**: 장애 감지 → 자동 교체
> 3. **부하 분산**: 트래픽 균등 분배

## Auto Scaling Group (ASG)

### 스케일링 정책 유형
| 정책 | 트리거 | 특징 |
|------|--------|------|
| 대상 추적 (Target Tracking) | 지표 목표값 유지 | 가장 간단, 권장 |
| 단계 스케일링 (Step) | CloudWatch 경보 + 단계 | 세밀한 제어 |
| 단순 스케일링 (Simple) | CloudWatch 경보 | 쿨다운 기간 후 1회 조정 |
| 예약 스케일링 (Scheduled) | 시간 기반 | 예측 가능한 부하 |
| 예측 스케일링 (Predictive) | ML 기반 예측 | 미리 스케일 아웃 |

> [!tip] 시험 핵심
> "CPU 70% 유지" → 대상 추적
> "트래픽이 월요일 오전에 집중" → 예약 스케일링
> "사전에 미리 준비" → 예측 스케일링

### ASG 헬스 체크
```
EC2 헬스 체크 (기본): EC2 상태만 확인
ELB 헬스 체크 (권장): 애플리케이션 레벨 확인
→ 비정상 인스턴스 자동 교체 (종료 + 새 인스턴스 시작)
```

### Launch Template vs Launch Configuration
| 항목 | Launch Template | Launch Configuration |
|------|-----------------|----------------------|
| 버전 관리 | ✅ | ❌ |
| Spot + On-Demand 혼합 | ✅ | ❌ |
| 권장 여부 | ✅ 권장 | 구버전 |

## 로드 밸런서 (ELB)

### 유형 비교
| 유형 | 레이어 | 라우팅 기준 | 용도 |
|------|--------|-------------|------|
| ALB | L7 (HTTP/HTTPS) | URL 경로, 호스트, 헤더 | 웹 앱, 마이크로서비스 |
| NLB | L4 (TCP/UDP) | IP + 포트 | 고성능, 낮은 지연시간, 정적 IP |
| GLB | L3 | IP 흐름 | 방화벽/IDS 인라인 배치 |
| CLB | L4/L7 | 기본 | 레거시 (구버전) |

> [!tip] ALB 주요 기능
> - **경로 기반 라우팅**: /api → 서버, /image → S3
> - **호스트 기반 라우팅**: api.example.com vs www.example.com
> - **스티키 세션**: 동일 클라이언트 → 동일 대상
> - **Lambda 대상**: HTTP 요청을 Lambda로 전달

> [!tip] NLB 선택 기준
> - **정적 IP** 필요 (ALB는 동적 IP)
> - **고성능**: 초당 수백만 요청, 낮은 지연시간
> - **비 HTTP 프로토콜**: TCP, UDP, TLS

### Connection Draining (등록 취소 지연)
- 기존 연결 완료 대기 후 인스턴스 제거 (기본 300초)

## 멀티 AZ 패턴

```
리전 (ap-northeast-2)
├── AZ-a: EC2 + RDS Primary
├── AZ-b: EC2 + RDS Standby
└── AZ-c: EC2 (optional)
      ↑
     ALB (모든 AZ에 자동 배포)
```

> [!warning] 최소 HA 구성
> ALB는 최소 **2개 AZ** 필요
