### 오답 메모

**RDS Multi-AZ 장애조치 메커니즘 (DNS 플립)**
- 혼동: 장애 시 스냅샷에서 새 인스턴스가 복원된다고 생각함 (B 선택)
- 핵심: Multi-AZ는 스탠바이가 동기 복제 중 → 장애 시 DNS CNAME이 자동으로 스탠바이를 가리킴. 스냅샷 복원 아님. 엔드포인트 주소 변경 없이 60~120초 내 전환

**DR 전략 선택 (Pilot Light vs Backup & Restore)**
- 혼동: "저비용 + RTO 최소화" 조건에서 Backup & Restore를 선택함 (A 선택)
- 핵심: Backup & Restore = 가장 저렴하지만 RTO 가장 길다(수 시간). Pilot Light = 핵심 컴포넌트만 항상 가동 → RTO 수십 분. "저비용이면서 RTO 단축" → Pilot Light
